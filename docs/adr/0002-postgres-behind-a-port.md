# ADR 0002: PostgreSQL for dossiers, behind a repository port with an in-memory adapter

Date: 2026-09-08. Status: accepted.

## Context

Dossiers must survive restarts in production. Every free hosting option has an ephemeral disk,
so a local SQLite file is not an option there. Locally, requiring a database just to try the
server would hurt the first-run experience and slow down unit tests.

## Decision

- `DossierRepo` (src/kyb_mcp/db/repo.py) is a small `Protocol`: create / get / list /
  add_note / set_status.
- `PostgresDossierRepo` is the production adapter: psycopg 3 async pool, idempotent
  `schema.sql` applied at startup, one engine locally (Docker Compose) and in production
  (Neon free tier).
- `InMemoryDossierRepo` is selected automatically when `DATABASE_URL` is unset. It powers
  `uv run kyb-mcp` with zero setup and the tool-level tests.
- The Postgres adapter has its own integration test, run whenever `KYB_TEST_DATABASE_URL` is
  set. CI always sets it (service container).

## Consequences

- Tool code never sees SQL; swapping the store is a one-line change in the lifespan.
- SQL is hand-written (no ORM): the schema is two tables and the queries are few. An ORM
  would add a dependency without removing any code that matters here.
- Ids are generated by the application (`d_<12 hex>`) so both adapters behave identically.
